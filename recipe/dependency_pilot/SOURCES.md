# Source and semantics ledger

- Main engineering baseline: this verl-agent checkout, `24305ac85b5c7456ed2c0f851b12d70bda45823d` (Apache-2.0). Reused `TrajectoryCollector.vanilla_multi_turn_loop`, collector preprocessing/flattening, unchanged `gigpo/core_gigpo.py`, existing `verl/utils/tracking.py` SwanLab backend, ALFWorld/AppWorld prompt templates and parsers. No BEACON code or reward shaping imported.
- ScienceWorld: official release **1.2.3**, commit `5d569f9e4ff43ab6242a3622f7e25f9bc367ccd1`, Apache-2.0. The adapter calls the installed public API; source is inspected, not copied. Each run records package version, wrapper hash and bundled JAR hash.
  - [Python wrapper](https://github.com/allenai/ScienceWorld/blob/5d569f9e4ff43ab6242a3622f7e25f9bc367ccd1/scienceworld/scienceworld.py): `step` returns a delta score; wrapper `done` also includes move limits and negative score. The reset look is recorded separately from generated agent turns.
  - [Goal sequence](https://github.com/allenai/ScienceWorld/blob/5d569f9e4ff43ab6242a3622f7e25f9bc367ccd1/simulator/src/main/scala/scienceworld/tasks/goals/Goal.scala): failed goals score -1; completion requires all ordered subgoals. Partial scoring includes optional unordered conditions. Pilot success uses **raw simulator score >= 1 AND native simulator completion**, not wrapper done plus positive score, and not the rounded integer score alone.
  - [Electric circuit tasks](https://github.com/allenai/ScienceWorld/blob/5d569f9e4ff43ab6242a3622f7e25f9bc367ccd1/simulator/src/main/scala/scienceworld/tasks/specifictasks/TaskElectricCircuit.scala): plain power requires correct focus and powered target; renewable/nonrenewable adds the specified power-source condition. Unordered scoring includes location and wiring events. A score increase is therefore not automatically a physical preparation label.
  - Native `get_valid_action_object_combinations` contains broad electrical candidates. Pilot records candidate membership but leaves execution validity unknown rather than equating the two.
- Qwen checkpoint: `Qwen/Qwen2.5-1.5B-Instruct`, revision `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`. Download manifest stores actual file sizes/SHA256; LFS weight hash checked against Hub metadata. No reference path is supplied to the actor.
- ALFWorld: existing HPC `alfworld-py310-v1` is accessed through a child Python process when `ALFWORLD_PYTHON` is set. Official train and valid_seen games are enumerated from installed files, checked by hash and fixed on reset; valid_seen is labelled official dev (source split retained). No test/valid_unseen tuning is performed. Public API from `alfworld==0.4.2`; Linux path awaits execution on Orion.
- AppWorld: [official API and installation](https://github.com/StonyBrookNLP/appworld), PyPI version `0.1.3.post1` for the separate Python 3.11 environment. Only installed `load_task_ids('train'/'dev')` IDs are candidates. Initial random candidates are **not yet semantically validated dependency tasks**. Evaluation uses native `evaluate().success` at the endpoint. No code from its task solutions/evaluators is given to the actor.
- SwanLab: installed SDK `0.10.2`; existing Tracking calls SDK login (this SDK defaults `save=False`). Pilot defines an explicit `analysis/batch_idx` axis and uploads only summary scalars and plots. Raw records and secrets are not included in config or report uploads. Offline/disabled paths retain local files.

The upstream collector observer is absent unless attached explicitly by the pilot. No upstream reward, advantage, loss, sampler, training default, or validation split is changed.
